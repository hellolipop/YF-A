# AlphaDesk · A股 / 美股实时分析终端

本地单机运行的行情分析终端：多数据源降级取数、十三个视图（市场 / 自选 / 个股 / 选股 / 买入扫描 / AI 选股 / 模拟交易 / 盘口事件 / 回测 / 跟踪 / 运行状态 / 预警 / 资讯）、服务端统一策略引擎（回测、持续跟踪、参数寻优、AI 选股共用同一份实现）、**SSE 实时推送**（行情 / 研判变化 / 成交回报）与**模拟交易 + 下单指令接口**，对接公开行情接口，本地运行，不上传任何账户信息。

> 本项目为研究与学习用途，数据来自公开接口，可能存在延迟或缺失，不构成任何投资建议。

## 二、架构

v2 的核心变化是**把策略实现收敛到服务端一份**。此前回测在浏览器里算、跟踪在服务端算，同一策略存在两套代码，结论可能互相矛盾。现在：

```
web/                       前端：只负责展示与画图
  views/backtest.js   ─┐
  views/tracker.js     ├─►  POST /api/backtest · /api/strategy/*  ─┐
  views/features.js   ─┘                                            │
                                                                    ▼
core/                       服务端：策略与撮合的唯一实现
  indicators.py    指标（唯一实现，MA / EMA / MACD / RSI / BOLL / KDJ / ATR / OBV）
  strategies.py    策略注册表（7 类策略 + 参数空间声明）
  kelly.py         凯利公式仓位（离散 / 连续 / 分数凯利 / 组合分配与整手取整）
  forecast.py      概率预测（状态分位编码 + 相似状态回找 → 条件分布 → 中位路径与上下轨）
  advisor.py       AI 选股编排（多策略共识 + 共识回放统计 + 凯利 + 预测 → 建议与交易计划）
  fills.py         成交模型（可插拔：次根开盘 / 当根收盘 / 固定基点 / 盘口深度加权）
  portfolio.py     账户与持仓（只管钱和券，不产出信号）
  metrics.py       绩效指标（25 项，收益与成本分开核算）
  stream.py        实时推送中枢（SSE：通道复用 / 背压 / 重放 / 上游限流 / 研判差分）
  trader.py        模拟交易引擎（配置与风控闸门 / 委托单 / 多标的账户 / 成本口径）
  storage.py       SQLite 持久化（分表 + schema 版本 + 迁移，v3 起含 AI 选股记录、v4 起含交易四表）
  runner.py        引擎编排（生命周期回调 + 常驻推进 + 回测 + 寻优）
  notify.py        通知渠道（Webhook 事件化）
  logs.py          结构化日志（JSONL + 内存环形缓冲）
providers/                  数据源
  features.py      集合竞价 / 分笔 / 龙虎榜 / 涨停梯队
server.py                    HTTP 层（路由 + 静态文件 + 数据源降级）
```

**分层与生命周期**：引擎按「数据源 → 策略 → 撮合 → 账户 → 绩效 → 持久」分层，每层可独立替换；推进顺序固定为 *执行上一根挂起信号 → 风控（止损止盈）→ 评估本根信号 → 记录权益*，并统一派发 `on_run_start / on_signal / on_fill / on_exit / on_skip / on_error / on_run_revised / on_run_paused` 事件。

**存储**：SQLite（Python 标准库，非第三方依赖），表为 `runs / trades / equity / signals / logs / meta`，schema 版本记录在 `meta` 表中并提供迁移入口，支持从 v1 的单文件 JSON 自动迁移且不改变既有统计。

## 三、策略引擎

### 3.1 成交模型（可插拔）

| 模型 | 成交价口径 |
| --- | --- |
| `nextOpen`（默认） | 信号次日开盘价，按账户滑点比例让价（与 v1 行为一致） |
| `closeFill` | 信号当根收盘价成交，更激进的成交假设 |
| `fixedBps` | 开盘价 + 固定基点，并叠加成交量参与度折算的冲击成本 |
| `depthWeighted` | 买入吃卖档、卖出吃买档，按档位成交量加权求均价；盘口深度不足或缺失时按振幅与参与度近似冲击 |

每笔成交同时记录**信号价**与**成交价**，两者差额作为实现滑点落库，因此可以回答「账户级滑点参数」与「实际成交偏差」之间的差异来自哪里。

### 3.2 绩效口径

收益与成本分开核算：`cost_total = fee_total + slippage_total`。指标包含累计 / 年化收益、年化波动、夏普、索提诺、卡玛、最大回撤及其持续天数、胜率、盈亏比、期望值、平均持仓、持仓占比、Alpha、Beta、单日 VaR(95%)、最好 / 最差单日、月度分解等 25 项。

累计方式可显式选择：`compound`（几何累乘，复利口径）或 `simple`（算术累加，单利口径）。

### 3.3 资金约束是显式暴露的

A股按 100 股/手取整。若初始资金买不起一手（例如 10 万本金买贵州茅台约需 12.9 万），买入信号会被跳过，并在回测结果、任务统计与信号日志三处同时计数，回测视图会给出「把初始资金提高到 X 并重跑」的一键修复。

### 3.4 调整任务

跟踪任务的参数分为两类：

| 类别 | 字段 | 行为 |
| --- | --- | --- |
| **即时生效** | 名称、备注、观察目标、手续费、滑点、止损止盈、参与度、累计口径、通知地址 | 已产生的交易、权益与统计**完全不变**，只影响后续成交与展示口径 |
| **需重置并重新回溯** | 策略、策略参数、周期、复权方式、初始资金、最小交易单位、观察期窗口 / 起点、成交模型 | 会改变信号逻辑或资金规模，必须先清空既有记录再重新回溯 |

未勾选「重置并重新回溯」时保存被禁用且服务端二次拦截；每次调整写入变更记录（最多 30 条）；校验失败时不会写入任何字段（先在副本校验再整体提交）。

## 四、AI 选股

### 4.1 结论由四条可验证的证据合成

不做黑箱打分：每条证据都单独放在响应里，前端与用户都能复核每一票、每一笔样本、每一个分位点，综合评分与置信度还各自附带分量明细（`scoreParts` / `confidenceParts`）便于归因。

| 证据 | 字段 | 口径 |
| --- | --- | --- |
| 多策略方向共识 | `ensemble` | 7 个策略在**当前这根K线**上的多空状态投票；净票 = 买票 − 卖票，取值 ±7 |
| 历史统计优势 | `edge` | 用「净票 ≥ +2 建仓、≤ −1 离场、期末强制平仓」这条共识规则回放同一段历史，逐笔记录**信号级单笔收益率**（已扣手续费与滑点，与仓位无关） |
| 凯利仓位 | `kelly` | 优先离散凯利 `f* = (p·b − q)/b`（胜率 × 赔率）；样本不足时退回连续凯利 `f* = μ/σ²`（μ、σ 由条件分布的分位差估计） |
| 概率预测 | `forecast` | 历史相似状态回找 → 条件分布 → 中位路径与 5% / 95% 上下轨 |

**两套口径必须分开看**：`core/strategies.py` 的**触发信号**（金叉 / 死叉 / 突破，稀疏、事件式）只用于 **K 线图上的买卖标记**；本模块的**方向状态**（快线在慢线上方 / RSI 处于超卖区，稠密、状态式）用于**共识票数与统计优势回放** —— 同一根K线上通常只有 0~1 个策略触发，事件式信号凑不出共识。两者共用同一份 `core/indicators.py`，且方向状态的周期参数直接取自 `core/strategies.py` 的参数表默认值，不在本模块二次硬编码。

### 4.2 建议档位与仓位

档位由「评分 + 置信度 + 凯利权重 + 风险红线」共同裁定，**风险红线优先**（历史最大回撤 ≥ 55% 或年化波动 ≥ 90% 直接给「回避」）：

| 档位 | 触发条件 |
| --- | --- |
| 买入 | 评分 ≥ 68 且置信度 ≥ 25% 且凯利权重 > 0 |
| 增持 | 评分 ≥ 58（或评分达标但置信度 / 仓位未过完整买入条件） |
| 持有 | 评分 ≥ 45 |
| 减仓 | 评分 ≥ 36 |
| 卖出 | 评分 < 36 且共识净票 ≤ −2 |
| 观望 / 回避 | 评分偏弱但空方共识不足 / 触发风险红线或数据不足 |

**建议档位是总闸门，凯利只决定闸门内的仓位大小**：只有「买入 / 增持」会参与本次资金分配，「持有 / 减仓 / 卖出 / 观望 / 回避」一律按 0 仓处理（行内仍保留「如果建仓会是多少」的参考权重，以及被拦下的原因）。仓位再经三道收敛：

1. **分数凯利**：`weight = f* × 折扣`（默认半凯利），并受单只权重上限约束；
2. **样本量收缩**：`f_used = f* × n/(n+20)` —— 11 笔样本只拿到 0.35 的信任度，避免小样本估出的赔率（常见 10 倍以上）被当成真值直接放大成满仓；
3. **组合归一化 + 整手取整**：等比缩放到计划仓位（1 − 现金缓冲），按 A股 100 股 / 美股 1 股就近取整；超预算则按比例缩减并向下取整。就近取整可能让实际权重略高于计划上限（最多半手），此时界面会显式提示。

### 4.3 预测的定位

`forecast` 回答的是「历史上长得像现在的时候，后面 h 根K线实际是怎么走的」，输出的是**历史条件分布**（分位数、上涨概率、样本量、置信度、中位路径与上下轨），不是点位预测，也不是收益承诺。防未来函数：相似窗口必须同时满足「其未来 h 根可观测」与「与当前窗口不重叠」；样本不足时降级为历史整体分布并给置信度打半折，降级原因写在字段里。

### 4.4 单位口径（前端消费约定）

| 类别 | 字段 |
| --- | --- |
| 小数 ratio（0.25 表示 25%） | `edge.winRate` `forecast.upProb` `confidence` `kelly.weight` `portfolio.totalWeight` |
| 百分数（1.494 表示 1.494%） | `changePct` `forecast.expectedReturn` `risk.atrPct` `risk.vol` `risk.maxDrawdown` |
| 原始比值 / 价格 / 股数 | `edge.payoff` `plan.riskReward` `kelly.fStar` `kelly.amount` `kelly.shares` `score`（0~100） |

多市场混批时**不做汇率换算**：A股与美股按各自本币口径分配本金与现金，权重之和才是总仓位。

### 4.5 图上表达

个股详情页在**日K**周期下会把本次研判画到 K 线上：AI 建议标记（带文字标签，配色与策略触发信号区分）、交易计划线（建议买入 / 目标1 / 目标2 / 止损）、右侧预测带（5%~95% 面积填充 + 中位虚线 + 末端「预测」标注）。分时 / 分钟 / 周月 K 不叠加（图表结构不同），界面会明确说明当前周期不支持，而不是假装已叠加。

### 4.6 记录持久化与事后复盘

每次批量研判（列表视图提交）会落一条记录，个股详情页可手动「保存本次研判」。记录存在与策略跟踪**同一个 SQLite 库**（`data/alphadesk.db`）里，两张表：

| 表 | 存什么 |
| --- | --- |
| `advisor_runs` | 一次研判的上下文与汇总：时间、市场、参数（窗口 / 本金 / 凯利折扣 / 单只上限）、来源、备注、置顶、标的数 / 已识别数、买入数、总仓位、建议分布、代码清单、组合分配、免责声明与模型口径 |
| `advisor_items` | 逐只结论：代码 / 名称 / 档位 / 评分 / 置信度 / 凯利权重与股数 / 预测 / 交易计划价位，外加完整行 JSON 供「载入」原样回放 |

界面能力：历史记录列表（市场 / 档位 / 关键词 / 只看置顶筛选）、**载入**（把当时的结论与组合分配原样回放到主表，并暂停 60 秒自动刷新避免被实时结果覆盖）、**复盘**、备注（行内编辑，回车或点「保存」）、置顶、删除、清空全部。

**复盘**用保存之后真实发生的行情检验当时的建议：给出每只标的的保存价 / 最新价 / 已经过多少个交易日 / 至今涨跌 / 5 根与 20 根后的收益，判定「命中 / 未命中 / 未到期 / 中性不计 / 无数据」，并汇总命中率（看多组与看空组分开）、平均收益、已建仓部分的加权收益与占本金收益。判定口径是用**最短的已到期窗口**（默认 5 根），未走满的一律计为「未到期」；「持有 / 观望」属中性档位不计入命中率；收益**不含手续费与滑点**。

**保留策略**：默认保留最近 500 条**未置顶**记录，超出的自动清理（置顶记录永不自动清理），可用 `AD_ADVISOR_KEEP=1000` 调整。实测单只标的约 9 KB（3 只标的的一条记录 26.5 KB），所以记录里**不保存预测带路径**（预测带锚定在保存时的价格上，事后回看没有意义），但买卖标记与交易计划保留。

### 4.7 实时行情推送（SSE）

用 SSE 而不是 WebSocket 的理由：本项目坚持零第三方依赖，WebSocket 要手写握手 / 掩码 / 帧解析，出错面积大；推送方向本来就是单向的（服务端 → 浏览器），反向操作继续走普通 POST，语义更清晰，也便于用 `curl -N` 直接验证。

| 通道 | 端点 | 节拍 | 事件 |
| --- | --- | --- | --- |
| 行情 | `GET /api/stream/quotes` | 默认 3 秒（1~60 可调） | `ready` `quotes` `error` |
| 研判 | `GET /api/stream/advisor` | 默认 30 秒（10~600 可调） | `ready` `snapshot` `change` `pulse` `error` |
| 交易 | `GET /api/stream/trade` | 事件驱动（无节拍） | `ready` `order` `fill` `account` `config` `note` `error` |

几个刻意的设计：

- **通道复用**：通道键 = 类型 + 订阅参数，因此多个浏览器标签页订阅同一批标的只共享**一次**上游请求；上游还有全局最小间隔（1.2 秒）保护，避免把公开行情接口变成压力源；
- **只在实质性变化时推**：`advisor` 通道每 30 秒重新研判，但只有「档位变了 / 评分摆动 ≥5 / 计划价位变了 / 上涨概率摆动 ≥10% / 期望收益摆动 ≥1.5% / 凯利权重摆动 ≥2%」才会推 `change`，其余情况推 `pulse`（已检查 N 只、无变化）—— 让用户知道系统在干活，而不是用静默伪装成「一切正常」；价格跳动由 `quotes` 通道负责，不算研判变化；
- **背压**：每个订阅者一条有界队列（64），读得慢就丢**最旧**事件并累加 `dropped`（`/api/stream/status` 可见）。绝不因为一个慢客户端阻塞发布线程；
- **断线恢复**：浏览器 `EventSource` 自带重连并携带 `Last-Event-ID`，服务端每个通道保留最近 32 条事件做有限重放（非法游标按「无游标」处理，不会因为一个负数就补发整段历史）；
- **降级**：`web/js/stream.js` 在「浏览器不支持 / 连续 3 次错误 / 连接被判定关闭」时自动切到轮询（默认 15 秒），恢复后自动切回，状态在界面上以 chip 如实显示（已连接 / 连接中 / 已降级为轮询 / 不支持）。
- **参数不合格快速失败**：`quotes` / `advisor` 通道缺 `symbols` 时直接返回 400 JSON，而不是开一条只会推 `error` 的长连接。

`GET /api/stream/status` 返回中枢状态（订阅者数、各通道节拍与上游调用量、被丢弃事件数）；`GET /api/stream/test?kind=quotes&symbols=600519` 做一次真实上游自检，用来区分「上游拿不到数据」与「推送链路有问题」。

### 4.8 模拟交易与自动交易接口

**先把边界说清楚**（这段是功能的一部分，不是免责套话）：

- 本工具**不连接任何券商通道，也不会产生真实委托**。所谓「自动交易」= 按 AI 建议与风控规则生成**委托意图**，在**本地模拟账户**里按真实报价成交，或把意图交给你自己的桥接系统去执行；
- 自动交易**默认关闭**，且默认 `dryrun`（只生成计划、不成交、不改账户）。要真正模拟成交必须显式开启 `enabled` 并把 `mode` 改成 `paper`；
- `confirmToken` 是**防误触口令**，不是安全边界（它会随配置接口返回，供前端填入执行口令框）。真正的安全边界是「不要把这个端口暴露到不可信网络」。

**从建议到委托**：`plan`（研判 → 风控闸门 → 落库为 `pending`）→ `execute`（按最新报价成交，需口令）→ 或 `export` 给外部系统 → 外部系统执行后 `ack` 回执。11 道闸门逐条留痕（每条拦截都会在 `skipped` 里写明代码、档位与原因，绝不静默丢弃）：总开关 → 白名单 → 数据可用性 → 价格有效性 → 置信度门槛 → 当日委托上限 → 持仓只数上限 → 减仓开关 → 持仓存在性 → 单笔金额上限（超出**缩减**而非跳过）→ 单只权重上限与可用现金。

**仓位口径**与 AI 选股一致：优先用研判给出的**可执行金额**（`kelly.amount`，已按整手取整），再取 `min(单笔上限, 单只上限, 可用现金)`，按 A股 100 股 / 美股 1 股**向下**取整到整手；不足一手就落到「可用资金不足一手」的 skip。成交成本与回测、统计优势同口径：买入价 = 报价 ×(1+滑点)、卖出价 = 报价 ×(1−滑点)，双边按费率计费；加仓均价 `(原成本 + 本次含费成本) / 新数量`，减仓不动均价并累计已实现盈亏。

**定时调度（真正的「自动」）**：`interval` 不是摆设 —— 服务端有一个常驻调度线程按它周期性走完整条链路（研判 → 风控闸门 → 落库 → 可选成交），并把委托与成交事件推到 `trade` 通道。

三层开关**默认全关、缺一不可**：`enabled`（自动交易总开关）→ `scheduler`（定时调度）→ `autoExecute`（自动成交，且只有 `mode=paper` 才会成交）。也就是：只开前两层 = 无人值守地出计划；三层全开 = 无人值守地模拟成交（仍然只发生在本地模拟账户）。

其它几条刻意的设计：

- **默认只在交易时段内扫描**（A股 09:30–11:30 / 13:00–15:00，美股按 13:30–21:00 UTC 的夏令时/冬令时并集），按 **UTC** 判定而不是本机时区 —— 用户机器未必在 Asia/Shanghai，写死 UTC 才不会因为时区设置而判错开市；`ignoreMarketHours` 可关掉判断，供演示与回放；
- **同一跳过原因只计一次**：调度线程每 5 秒醒一次，若「非交易时段」这种整晚成立的原因每次都累加，一天就能堆到上万次，指标会彻底失去意义；
- **跳过永远有原因**：`lastSkip` / `lastError` 会写进状态接口，界面上有一行「为什么现在没动作」，从「未开总开关」到「非交易时段」再到「标的池为空」逐条说明 —— 一个静默不动的自动化系统比一个报错的系统更难用；
- **取不到实时报价时回退到计划价**（并把 `priceSource` 标成 `snapshot`、写一条 `scheduler.price_fallback` 日志），而不是把全部委托记成 rejected —— 后者在界面上表现为「自动交易全是拒单」，用户会以为策略坏了；
- **研判整体失败记为错误**，而不是「已生成 0 笔计划」：一次全量取数失败看起来像「本轮无操作」，是最危险的静默失败；
- 单次调度不重叠（锁）、异常不会让调度线程退出（写进 `lastError` 并在下一轮继续尝试），否则一次网络抖动就会让「自动」永久失效而没人察觉。

**账户**：`dryrun` 与 `paper` 各自一本账（`account_id = "<mode>:<market>"`），演练不会污染模拟成交账户。注意 `capital`（配置）是**仓位计算基准**，账户的 `initial`（本金）只在建仓时确定 —— 改 `capital` 不会重置已有账户，要改本金请用「重置模拟账户」。

### 4.9 标的名称识别

输入往往不是代码：可能是中文名（贵州茅台）、简称（茅台 / 宁德）、拼音首字母（gzmt）、
带交易所前缀或后缀的代码（sh600519 / 000001.SZ）、或「代码:名称」的混合写法。识别层统一
把它们解析成 `{code, market, name}`，同时反向解决另一个问题：**只输代码时，界面与记录里
要显示真实名称**（服务端在取行情时用行情源返回的名称回填，零成本）。

**识别顺序（先本地后远端、先精确后模糊）**

| 顺序 | 手段 | 说明 |
| --- | --- | --- |
| 1 | 代码直判 | `600519` / `sh600519` / `000001.SZ` / `AAPL` / `BRK-B` —— 零成本、不依赖任何数据源 |
| 2 | 本地全市场名录 | 用个股列表快照建索引（A股 5500+ 只），做**名称精确 / 前缀 / 子串**与**代码前缀**匹配；快、可离线、不消耗第三方配额 |
| 3 | 远端搜索兜底 | 本地无命中时才打搜索接口，覆盖**拼音首字母、全拼与错别字**（自建拼音表在零依赖前提下维护成本太高，且股票名里还有多音字） |

**三类结果严格区分**，不做「取搜索第一个」：

- `code` / `name`：唯一命中，自动落定（并显示是名称完全匹配、前缀命中还是远端命中）；
- `ambiguous`：**命中多个候选时一律返回候选清单，由你在界面上选择**。「平安」同时命中
  平安银行、平安电工、中国平安 —— 静默取第一个会把分析对象换成另一只股票，而用户完全
  不会察觉，这类错误比「识别失败」危险得多。未选择前提交会被拦下并提示；
- `unknown`：本地与远端都没命中，如实说明试过哪些途径，而不是只丢一句「未识别」。

另外两点刻意的设计：**纯字母串在 A 股语境下先按名称识别**（`gzmt` 与美股代码长得一样，
先当代码会让「输拼音查茅台」永远得到一只不存在的美股；先当名称、找不到再当代码，两种
意图都能满足）；**远端只回显输入时标为「按代码处理」的猜测**（接口回显不等于这只股票
存在，界面用黄色 chip 标出「可能不存在」，与确定命中区分开）。

重复输入会合并：`600519 茅台 贵州茅台` 解析到同一只股票时只占一条，界面会说明
「输入 N 个 → 明细 M 条」，因为组合权重是按行分配的，重复行会把同一只股票的仓位吃掉多次。

### 4.10 买入扫描与买卖点位

**目标**：先回答「有什么值得买」，再回答「怎么买、在哪卖」。

扫描的执行顺序是刻意的（性能与诚实性都要求这样排）：**先用快照行过硬闸门**（几千只只需几毫秒）→ 通过的按成交额排序、**只对前 N 只取K线**（默认 60，避免几千次网络请求）→ 再做复合评分取前 M 只。因此界面上会如实写出「本次扫描 5559 只，通过硬闸门 1518 只，**因取样上限未评分 1493 只**」——不能让用户以为「全市场都算过了」。

评分口径来自本轮对开源项目的调研（InStock / zvt / Penny / DuckDB 三层过滤等）：

- **三道硬闸门先过滤**：流动性下限（成交额 ≥ 2 亿）、反追高（当日涨幅 ≤ 7%）、量能（量比 ≥ 1.2 或 5日/20日均额 ≥ 1.3）。没通过的不参与打分，逐条给出中文原因；
- **反「已经涨上天」**：近 60 日累计涨幅过高扣分（>150% 直接剔除）、近 60 日出现单日跌幅 > 7% 或两日累计 > 10%，并合成为 **0–10 风险分**（5–6 = AVOID，7+ = CRITICAL）；
- **A股短期偏反转、不是动量**（《中国A股市场动量效应和反转效应》实证；本工具持有 5–20 个交易日正落在短期区间）：所以 **RSI 50–68 给满分、RSI > 75 反而扣分**，不是「涨得越猛越好」；**低换手加分、高换手扣分**（换手率分组单调性 0.74，高换手组长期跑输）；
- **单指标不能独立成为买入理由**：Sullivan–Timmermann–White 用 7,846 条技术规则 + White's Reality Check 校正后，最好的规则不再显著。因此 `reasons` 里每条都带权重，不出现「因为 RSI 超卖所以买入」这种单因子结论；
- 结果是 **A(80–100) / B(65–79) / C(50–64) / D(35–49) / F(0–34)** 等级 + 一句话 `verdict`，界面主视觉只放等级、结论、分数、风险分四样。

**买卖点位**（`core/levels.py`）同样按调研结论落地：

- **止损用波动率自适应而不是固定百分比**：Chandelier Exit = 最高价(22) − 3×ATR(22)，配合更紧的 2.0×ATR(14)；并明确写出取舍（厂商级回测：固定止损胜率 38.2%/盈亏比 2.7、ATR 2.0× 47.6%/2.1、Chandelier(22,3) 51.3%/1.9 —— 波动率自适应在**期望值**上更优，而移动止损天然胜率更低、趋势中回吐更少）；
- **三段式止损**（freqtrade 的标准形态）：初始止损 → 移动止损启动价 → 移动后锁定价，三个数字都给，而不是一个孤零零的止损价；
- **四源支撑阻力交叉**：枢轴点（机械计算）、摆动高低点、成交量密集区（近似筹码）、均线，按 ATR 距离合并并标强度（强/中/弱）；
- **分批建仓**（2–3 档，权重和为 1，且**每档都必须高于初始止损**，否则该档剔除并给出警告）；
- **仓位由风险反算**而不是只靠凯利：`股数 = 本金 × 1% / (入场 − 止损)` 取整到整手（Van Tharp 的 1% 规则），并写明它的失效边界（不防跳空、滑点、相关性同时爆发、涨跌停无法成交）；
- **七条优先级退出**（第一个触发者胜出）：动量衰竭 / 移动止损 / 放量杀跌 / 支撑破位 / 止盈目标 / 滞涨 / ATR 止损 —— 推送与界面都直接说明**是哪一条规则触发的**，比只给一个价格有用得多；
- **避免假精确**：样本 < 60 根时所有价位降到 0.1 元精度并标注「参考」；`asOf` 用最后一根K线的时间而不是当前时间。

### 4.11 交易规则引擎

`core/rules.py` 把「下单与撮合必须遵守的规则」集中成一份口径（模拟交易、点位引擎、扫描器与界面提示共用），因为规则一旦在多个模块各写一份，就会出现「回测按 10% 判定、模拟成交按 20% 判定」这种**不会报错但会让收益算错**的矛盾。

| 项 | 口径 |
| --- | --- |
| 涨跌幅 | 主板 10%、创业板/科创板 20%、北交所 30%；风险警示股 10%（**2026-07-06 起由 5% 放宽**，旧口径可经 `stLimitRatio` 改回）；新股上市初期（主板/创业板/科创板前 5 日、北交所首日）与退市整理首日**不设限** |
| 涨跌停价 | 前收盘价 ×(1±比例) **四舍五入到 0.01 元**；两个边界补丁：价差不足 0.01 元按 ±0.01 元、结果低于 0.01 元按 0.01 元 |
| 费用 | 印花税**仅卖出单边** 0.05%；佣金双向、**不足 5 元按 5 元**；过户费 0.001% 双向；经手费 0.00341% 双向（北交所 0.0125%） |
| T+1 | 可卖 = 昨仓 − 今日已卖 − 冻结；**当日买入不可当日卖出**，自动与手动路径一律适用 |
| 最小单位 | 主板/创业板 100 股整数倍；科创板 200 股起、超过部分可 1 股递增；**卖出时不足一手的余额必须一次性卖出**；美股 1 股 |
| 时段 | 09:15–09:25 集合竞价（09:20 后不可撤单）、**09:25–09:30 不接受任何申报**、09:30–11:30 / 13:00–15:00 连续竞价、14:57–15:00 收盘集合竞价（不可撤单）、15:05–15:30 盘后固定价格（按收盘价、时间优先） |
| 撮合 | 涨停买不到、跌停卖不出（按时间优先排队，无对手单则零成交）；连续竞价限价申报有 ±2% 价格笼子（越界为废单） |

**本轮把模拟交易引擎接到了这份口径上**：费用从「单一双边费率」换成逐项口径（1 万元买入从旧口径的 3 元变成真实的 **5.44 元**，高出 80%）、T+1 真正生效（此前同日买卖可成交，等于给模拟盘开了 T+0 后门）、涨停价买入会被「交易规则」拒单（此前会在纸面上凭空造出连板股的虚假收益）。

`GET /api/rules` 会把**规则版本、来源链接、以及「未取得权威来源的项」**一起返回，界面上原样展示 —— 后者包括卖出资金 T+0 可用、证管费费率、美股最小单位与费用默认值等，宁缺勿造。

### 4.12 策略跟踪：推进口径与健康度

**推进入口用日期游标，不用位置索引。** 引擎每次固定取 800 根K线，拿到的是一个**滑动窗口**，
位置索引只在「窗口不滑、序列只增」时才成立。这一点踩过真实事故（2026-09-17）：

```
首次取到的根数比 800 多 1（801）→ barProcessed 被推到 801
此后窗口只有 800 根 → start_i(801) >= complete_n(≤800) 永远成立
→ replay 分支再也不进入，任务从创建起冻结在当时的持仓状态
```

而 `tickCount` 照涨、`lastBarTime` 照更新（由盘中分支写入），界面上完全看不出异常 ——
用户看到的现象是「策略跟踪里全是空仓」，实际是引擎一整天一根K线都没消化。

现在两条都做了：

- **游标 = 最后一根已处理的已收盘K线的日期**（`lastBarDate`）。窗口怎么滑都不会指错；
  没有更新的K线时返回 `complete_n`，不会越界重放（重复处理同一根K线会凭空造出交易）。
- **旧任务一次性迁移**：迁移口径取「`max(创建日, 最后执行日, 各笔交易的进出场日)`」。
  这些日期之后在冻结事故中确实从未被处理过，而重放「无事件区间」是幂等的
  （不会造出新交易、也不重复计数已有交易），因此迁移不会重复计数。迁移后该任务会标记
  `cursorMigrated`，便于事后排查。
- **健康度可见**：概览与详情都返回 `lastBarDate`（已处理至）、`availableTo`（最新K线）、
  `lagDays` 与 `stalled`；跟踪列表的状态列直接显示「至 09-17」，滞后 ≥5 天时变成
  黄色「落后 N 天」并给出提示。**滞后阈值取 5 天而不是 1 天**：盘中「正在形成的那根」
  天然差 1 天，按 1 天报警会天天误报，反而让人忽略真正的停滞。

### 4.13 交易计划的方向语义（建仓 / 离场）

计划里的四个价位在不同档位下的**含义是相反的**，这一点必须讲清，否则会出现
「止损价高于建议买入价」这种看起来自相矛盾的显示（实际发生过：冰轮环境 000811
档位「回避」时显示「建议买入 38.66 / 止损 42.04」）。

| 档位 | `direction` | 几何 | 那个上方/下方的价是什么意思 | `tradeable` |
| --- | --- | --- | --- | --- |
| 买入 / 增持 / 持有 / 观望 | `long` | 止损 < 入场 < 目标1 < 目标2 | 止损（跌破离场）、上行目标 | `true` |
| 减仓 / 卖出 / 回避 | `exit` | 失效价 > 参考价 > 下行目标1 > 下行目标2 | 参考价取现价；**上方是「涨破则离场判断失效」**；下方是下行参考目标 | `false` |

服务端为此显式给出四个字段，消费方（界面、图表叠加层、导出、外部系统）照它渲染即可：

- `side`：中文方位（建仓 / 离场）；
- `tradeable`：能否据此**新开仓位**（只有 `long` 为真）；
- `inverted`：是否「失效价在上、目标在下」的反向口径；
- `labels`：各方位在该方向下的正确中文标签（离场时为「参考价（不新开仓位）」「离场失效价（涨破则判断失效）」「下行目标1/2」）。

界面侧（`web/js/views/detail.js` 的计划区块、`web/js/chart.js` 的叠加线与图例）**必须按
`direction` 渲染标签与配色**，并在离场口径下明确标注「不新开仓位」；`labels` 缺失时
按方向兜底（因此旧接口/缓存数据也不会显示错）。

### 4.14 无感刷新（更新数据不重构图）

轮询或推送刷新时把容器 `clear()` 再整块重建，会**闪一下**，还会丢掉滚动位置、行 hover、
正在输入的焦点，以及画布内容。前端为此统一改成「增量更新」：

`web/js/util.js` 的 `AD.dom` 提供三个原语（`web/js/ui.js` 的表格与各视图都基于它们）：

| 原语 | 语义 |
| --- | --- |
| `morph(oldEl, newEl)` | 结构相同就原地改写，**只写真正变化的文本/属性**；结构不同才换节点；`<canvas>` 与焦点输入框永不替换 |
| `paint(host, children)` | 把 `h()` 构造的游离子树合并进 host（最常用的一步到位写法） |
| `reconcile(host, items, {key, render})` | 带 key 的列表复用：行没变就不碰 DOM，顺序变化只做节点移动；行内监听读 `node.__row` 拿最新数据 |

`AD.ui.tbl` 的 `update(rows, keepSort)` 已改为按行 key 增量更新：表头只在排序列变化时重建，
表体、滚动位置与 hover 保持不变；需要换列定义时用 `setCols(cols)` 而不是重建整张表。

各视图的轮询 / SSE 路径统一为「首次创建并挂载实例 → 之后只 `update()` / `paint()`」：
自选股、市场榜单与异动、AI 选股结果与组合分配、历史记录、交易（持仓 / 委托 / 计划 / 调度器）、
策略跟踪（列表 / 详情 / 月度 / 逐笔）、系统日志、功能页各 tab、预警规则与触发记录、扫描状态条。
顶栏时段徽标（每秒刷新）从「重建两个节点」改为「只改文本」。

图表侧（`web/js/chart.js` + `web/js/views/detail.js`）额外做了四件事：

1. 图表实例按**形态**（分时 / K线）复用；周期与复权只走 `setOptions` + `setData`，
   切换周期不再重建 canvas；
2. `setData(bars, {keepView:true})` 在轮询刷新时保留用户的缩放与平移位置
   （按新增根数同步右移，仍看同一段），不再每次跳回最右端；
3. 刷新中 / 刷新失败改用容器右上角的 `is-busy` 角标（CSS `.is-busy::after`），
   **不再用「加载中」替换内容**；取数失败时保留旧图并提示（`is-warn`），只有本来就没有图时才显示空态；
4. `prepare()` 只在画布尺寸真的变化时才给 `canvas.width/height` 赋值，避免每次重绘都重新分配位图。

**仍然刻意重建的地方**（有意保留，不是遗漏）：含输入框的表单区块（交易配置、跟踪任务表单、
AI 选股参数与「识别结果」歧义选择）在刷新时不做原位复用，避免抢焦点或提交过期值；
纯用户点击触发的展开块（如点位面板）同样按原样重建。

回归测试：`tests/ui/seamless_refresh.js`（A 段离线断言「数据未变时零 DOM 写入」，
B 段在真实页面上断言表体 / 首行 / canvas 的节点身份跨刷新不变）。

## 八、已知限制

1. **服务停止期间不推进**：引擎是常驻线程，进程退出后不再累积；重启会补齐已收盘K线（按 `barProcessed` 断点续跑，不重复成交）。
2. **分钟级历史深度有限**：5/15/30/60 分钟 K线公开接口只提供数百根，回溯窗口会短于所选的月份；日 / 周 / 月 K线可完整回溯 1 年。
3. **分笔与竞价仅当日**：两个来源都不支持历史日期；涨停池仅最近约 20 个交易日；集合竞价的「未匹配量 / 撤单量」公开接口无来源，恒为空并标注原因。
4. **北交所（4/8 开头）无分笔与竞价数据**。
5. **回测模型限制**：单标的、全仓、未考虑涨跌停与流动性限制；成交模型是显式假设而非真实撮合，`depthWeighted` 在无盘口的历史区间会退化为冲击成本近似。
6. **旧数据成本为推算值**：v1 迁移的成交记录没有逐笔成本，按当时的费率与滑点反推并标记为「估算」，新产生的成交为实测记录。
7. **美股口径**：全市场约 1.4 万只，榜单与筛选基于成交额前 N 的活跃样本；分钟级 K线由分时聚合。
8. **前端图表仍为自研 Canvas**：缩放、十字光标、副图齐全，但没有画线工具。
9. **AI 选股记录会按上限自动清理**：默认保留最近 500 条未置顶记录，置顶记录不参与自动清理；被清理的条数在历史记录区块里如实展示（`retention.pruned`），不会静默丢弃。
10. **AI 选股的口径边界**：结论来自公开日线行情与统计模型。日线数百根样本通常只产出个位数到十几笔共识交易，「统计优势」的样本量普遍偏小，只作参考，不足以支撑参数调优；条件分布是历史统计而非预测；不含涨跌停、停牌、T+1、做空与杠杆约束，也不考虑基本面与消息面；多市场混批不做汇率换算。评分与档位用于横向比较，不是收益预测。
11. **实时推送是「长连接 + 线程」模型**：每个 SSE 客户端占用一个服务端线程，适合本机单用户；请勿把端口暴露到公网（既没有鉴权，也没有连接数上限）。
12. **异常断开的回收有延迟**：客户端被强杀（没发 FIN）时，服务端要等到后续写入失败才会回收订阅 —— TCP 发送缓冲有几十 KB，叠加 10 秒心跳，最长可能滞后约一分钟。期间该通道仍会拉上游数据，这是 SSE over TCP 的固有限制。
13. **模拟成交是「按最新可得报价一次成交」**：不模拟排队、部分成交、涨跌停封板与盘口冲击，也没有做空、融资与逐笔 T+1 结算；成本只含可配置的费率与滑点。它用于验证「策略与仓位规则是否自洽」，不等于真实成交结果。
14. **自动交易不接券商、`confirmToken` 不是安全边界**：详见 4.8。真正的报单需要你自己实现 `export` → 执行 → `ack` 的桥接系统。
15. **`capital` 与账户 `initial` 是两件事**：`capital` 是仓位计算基准，改动它会立刻影响后续下单规模；账户本金只在建仓/重置时确定，改 `capital` 不会重置已有账户。
16. **名称识别的能力边界**：拼音与错别字依赖远端搜索接口（本地名录只能做代码与中文名的精确/前缀/子串匹配，自建拼音表在零依赖前提下不划算）；美股本地名录只有活跃样本（约 400 只），其余美股代码由远端搜索与行情回填补名称。本地名录缓存 15 分钟，新股与更名最迟 15 分钟后可见。
17. **交易时段判断没有交易日历**：只按「周一到周五 + 时段」粗判，节假日会被判成开市。这对自动交易是安全的（节假日行情是静态的，生成的是与上一交易日相同的计划，不会产生错误成交），但会多打一次上游请求。美股时段取夏令时/冬令时的并集，前后各放宽 30 分钟，同样是有意为之。
18. **调度线程只在服务运行时存在**：关闭进程（或 `--no-engine` 启动）都不会自动调度，配置里的 `scheduler` 会在下次正常启动时恢复；`POST /api/trade/scheduler` 可手动拉起，便于联调。
19. **扫描只对成交额最大的前 N 只取K线**（默认 60）：通过硬闸门的通常有一千多只，其余**不参与评分**并在 `stats.truncatedByBarsLimit` 与界面上如实报出；提高取样上限会增加耗时（约每只 0.4 秒）。
20. **评级与点位是技术面产物，不是收益承诺**：所有评分/等级/概率都来自历史统计，样本量、区间与失败边界都已标注（如点位样本 < 60 根时降精度、复盘样本 < 30 笔时告警）；`/api/levels` 不给样本不足的「精确」价位。
21. **复盘的两套口径会不一致**（QuantStats 口径提醒）：周期口径按权益曲线逐点算「正收益周期占比」，逐笔口径按已完成交易算胜率 —— 一笔 5 天的交易在周期口径里可能被记成 3 胜 2 负，界面上分栏标注，不要混读。
22. **MAE/MFE 与持仓 bar 数通常不可用**：委托单里没有盘中价格路径，`core/review` 如实返回 None 并给告警，不用收盘价冒充。
23. **美股费用与最小单位是示例口径**：券商差异大且未取得权威来源，已在 `/api/rules` 的「未证实项」里列出，使用前请按自己券商调整。
