# AlphaDesk · A股 / 美股实时分析终端

本地单机运行的行情分析终端：多数据源降级取数、十个视图（市场 / 自选 / 个股 / 选股 / 盘口事件 / 回测 / 跟踪 / 运行状态 / 预警 / 资讯）、服务端统一策略引擎（回测、持续跟踪、参数寻优共用同一份实现），对接公开行情接口，本地运行，不上传任何账户信息。

> 本项目为研究与学习用途，数据来自公开接口，可能存在延迟或缺失，不构成任何投资建议。

## 二、架构

v2 的核心变化是**把策略实现收敛到服务端一份**。此前回测在浏览器里算、跟踪在服务端算，同一策略存在两套代码，结论可能互相矛盾。现在：

```
web/                       前端：只负责展示与画图
  views/backtest.js   ─┐
  views/tracker.js     ├─►  POST /api/backtest · /api/strategy/*  ─┐
  views/features.js   ─┘                                            │
                                                                    ▼
core/                       服务端：策略与撮合的唯一实现
  indicators.py    指标（唯一实现，MA / EMA / MACD / RSI / BOLL / KDJ / ATR / OBV）
  strategies.py    策略注册表（7 类策略 + 参数空间声明）
  fills.py         成交模型（可插拔：次根开盘 / 当根收盘 / 固定基点 / 盘口深度加权）
  portfolio.py     账户与持仓（只管钱和券，不产出信号）
  metrics.py       绩效指标（25 项，收益与成本分开核算）
  storage.py       SQLite 持久化（分表 + schema 版本 + 迁移）
  runner.py        引擎编排（生命周期回调 + 常驻推进 + 回测 + 寻优）
  notify.py        通知渠道（Webhook 事件化）
  logs.py          结构化日志（JSONL + 内存环形缓冲）
providers/                  数据源
  features.py      集合竞价 / 分笔 / 龙虎榜 / 涨停梯队
server.py                    HTTP 层（路由 + 静态文件 + 数据源降级）
```

**分层与生命周期**：引擎按「数据源 → 策略 → 撮合 → 账户 → 绩效 → 持久」分层，每层可独立替换；推进顺序固定为 *执行上一根挂起信号 → 风控（止损止盈）→ 评估本根信号 → 记录权益*，并统一派发 `on_run_start / on_signal / on_fill / on_exit / on_skip / on_error / on_run_revised / on_run_paused` 事件。

**存储**：SQLite（Python 标准库，非第三方依赖），表为 `runs / trades / equity / signals / logs / meta`，schema 版本记录在 `meta` 表中并提供迁移入口，支持从 v1 的单文件 JSON 自动迁移且不改变既有统计。

## 三、策略引擎

### 3.1 成交模型（可插拔）

| 模型 | 成交价口径 |
| --- | --- |
| `nextOpen`（默认） | 信号次日开盘价，按账户滑点比例让价（与 v1 行为一致） |
| `closeFill` | 信号当根收盘价成交，更激进的成交假设 |
| `fixedBps` | 开盘价 + 固定基点，并叠加成交量参与度折算的冲击成本 |
| `depthWeighted` | 买入吃卖档、卖出吃买档，按档位成交量加权求均价；盘口深度不足或缺失时按振幅与参与度近似冲击 |

每笔成交同时记录**信号价**与**成交价**，两者差额作为实现滑点落库，因此可以回答「账户级滑点参数」与「实际成交偏差」之间的差异来自哪里。

### 3.2 绩效口径

收益与成本分开核算：`cost_total = fee_total + slippage_total`。指标包含累计 / 年化收益、年化波动、夏普、索提诺、卡玛、最大回撤及其持续天数、胜率、盈亏比、期望值、平均持仓、持仓占比、Alpha、Beta、单日 VaR(95%)、最好 / 最差单日、月度分解等 25 项。

累计方式可显式选择：`compound`（几何累乘，复利口径）或 `simple`（算术累加，单利口径）。

### 3.3 资金约束是显式暴露的

A股按 100 股/手取整。若初始资金买不起一手（例如 10 万本金买贵州茅台约需 12.9 万），买入信号会被跳过，并在回测结果、任务统计与信号日志三处同时计数，回测视图会给出「把初始资金提高到 X 并重跑」的一键修复。

### 3.4 调整任务

跟踪任务的参数分为两类：

| 类别 | 字段 | 行为 |
| --- | --- | --- |
| **即时生效** | 名称、备注、观察目标、手续费、滑点、止损止盈、参与度、累计口径、通知地址 | 已产生的交易、权益与统计**完全不变**，只影响后续成交与展示口径 |
| **需重置并重新回溯** | 策略、策略参数、周期、复权方式、初始资金、最小交易单位、观察期窗口 / 起点、成交模型 | 会改变信号逻辑或资金规模，必须先清空既有记录再重新回溯 |

未勾选「重置并重新回溯」时保存被禁用且服务端二次拦截；每次调整写入变更记录（最多 30 条）；校验失败时不会写入任何字段（先在副本校验再整体提交）。

## 五、数据来源与降级

| 数据 | 主源 | 备用 | 说明 |
| --- | --- | --- | --- |
| A股报价 / K线 | 腾讯行情 | 新浪财经 | 分时与五档来自腾讯 |
| 美股报价 / K线 | 腾讯行情 | 东方财富 | 美股无公开五档，仅最优一档 |
| 全市场快照 / 榜单 / 板块 | 东方财富 | 新浪财经 → 本地快照 | 东财有突发限流，自动切换并在界面标注来源 |
| 集合竞价 / 分笔 | 东方财富 | 腾讯 | 仅当日，不支持历史日期 |
| 龙虎榜 | 东方财富 | 自动回溯最近交易日 | 当日无数据时回溯（跳过周末），界面标注实际日期 |
| 涨停梯队 | 东方财富 | 自动回溯最近交易日 | 接口仅保留最近约 20 个交易日 |

所有响应都带来源与抓取时间，缺失数据如实标注为「不可得」，不做估算填充。

## 六、快速开始

```bash
./start.sh                       # 一键启动并打开浏览器（默认 8848 端口）
python3 server.py --port 8848    # 手动启动
python3 server.py --no-engine    # 只跑 Web 服务，不启动策略推进线程
AD_STRATEGY_TICK=30 python3 server.py   # 调整引擎推进间隔（秒，默认 60）
AD_VERBOSE=1 python3 server.py   # 打印异常堆栈与通知调试信息
```

无需安装任何 Python 第三方依赖。数据目录 `data/` 会自动创建：`alphadesk.db`（SQLite 状态库）、`alphadesk.log`（结构化日志）、`*_snapshot.json`（行情快照兜底，用于断网降级）。

## 七、已知限制

1. **服务停止期间不推进**：引擎是常驻线程，进程退出后不再累积；重启会补齐已收盘K线（按 `barProcessed` 断点续跑，不重复成交）。
2. **分钟级历史深度有限**：5/15/30/60 分钟 K线公开接口只提供数百根，回溯窗口会短于所选的月份；日 / 周 / 月 K线可完整回溯 1 年。
3. **分笔与竞价仅当日**：两个来源都不支持历史日期；涨停池仅最近约 20 个交易日；集合竞价的「未匹配量 / 撤单量」公开接口无来源，恒为空并标注原因。
4. **北交所（4/8 开头）无分笔与竞价数据**。
5. **回测模型限制**：单标的、全仓、未考虑涨跌停与流动性限制；成交模型是显式假设而非真实撮合，`depthWeighted` 在无盘口的历史区间会退化为冲击成本近似。
6. **旧数据成本为推算值**：v1 迁移的成交记录没有逐笔成本，按当时的费率与滑点反推并标记为「估算」，新产生的成交为实测记录。
7. **美股口径**：全市场约 1.4 万只，榜单与筛选基于成交额前 N 的活跃样本；分钟级 K线由分时聚合。
8. **前端图表仍为自研 Canvas**：缩放、十字光标、副图齐全，但没有画线工具。
